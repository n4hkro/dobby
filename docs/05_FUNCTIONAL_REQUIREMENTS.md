# Dobby Functional Requirements

**Tarix:** 2026-04-24
**Status:** Təsdiqlənib
**Scope:** İstifadəçi və sistem davranışı üçün test edilə bilən funksional tələblər

Bu sənəd məhsul və arxitektura sənədlərində artıq bağlanmış davranışları requirement formasında toplayır. Məhsul kimliyi və sərhədlər [docs/01_PRODUCT_SCOPE.md](./01_PRODUCT_SCOPE.md), arxitektura ownership-i [docs/02_ARCHITECTURE_MAP.md](./02_ARCHITECTURE_MAP.md), failure semantics isə [docs/04_RESULT_VS_EXCEPTION_POLICY.md](./04_RESULT_VS_EXCEPTION_POLICY.md) ilə bağlanır.

## Phase taxonomy

- **P1-core** — Phase 1 release üçün mütləq davranışdır.
- **P1-if-time** — Release blocker deyil, amma vaxt qalsa Phase 1-də tamamlanır.
- **P2** — Sonrakı release-lərə saxlanır.

## Branch Shared Mode Addendum

Standalone requirements above remain canonical for Standalone mode.
`ADR-0056` and `ADR-0057` add Branch Shared documentation requirements:

- Branch Shared authoritative users, credentials, permissions, audit and shared
  business/plugin key-value data live in PostgreSQL over the branch LAN.
- Branch Shared devices keep only DeviceLocal profile/secrets/bootstrap and
  diagnostics material locally; local credential/permission mirrors are not
  created.
- First Owner creation is Standalone-only as a first-login behavior. In Branch
  Shared mode the first Owner is created during main-device BranchSetup
  provisioning, and seller devices cannot race to become Owner.
- Branch Shared unavailable behavior is fail-closed for shared auth and shared
  commands. Local diagnostics/setup evidence may be written, but it is not
  authoritative Branch Shared audit.

These Branch Shared requirements are Phase 1 documentation-pass requirements
only until a later approved Branch Shared skeleton implementation pass opens
code work.
