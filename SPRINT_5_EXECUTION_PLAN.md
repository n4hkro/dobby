# Sprint 5 Execution Plan — Login-First Auth, Sessions, and Owner Recovery

## 1. Sprint Summary

- Sprint number and title: Sprint 5 — `Login-First Auth, Sessions, and Owner Recovery`.
- Main goal: build offline-first login UI and runtime, local username/password/display-name credential flow with KDF floors and app-wide throttle, single-instance host coordinator acquired before login UI first paint, transactional first-user Owner bootstrap, single-active session lifecycle (create/lock/unlock/logout, absolute/idle timeout, deactivation invalidation, self-service password change), masked single-slot remember-me, and host-side `.dobbyrecoveryrequest` export plus `.dobbyrecovery` import (Sprint 5 TEST-ONLY signed ECDSA P-256 fixture evidence, 24h, one-use, device-bound fuzzy match) on top of the Sprint 4 protected persistence and DPAPI surfaces.
- Expected deliverable: a clean Dobby install can build the first Owner transactionally with optional `DisplayName`, render the documented pre-login login surface within ADR-0041 allowed workload, authenticate against the encrypted SQLite-backed `Users`/`Credentials` tables using the recorded `Pbkdf2Sha256` KDF policy with `[0,0,10,30,60]` throttle, maintain a single active in-process session bound by `SessionOptions` (8h absolute, 30m idle), manage lock/unlock and self-service password change, replace or clear the single `RememberMeSlot` per ADR-0038, refuse a second writable host instance via a coordinator acquired before login UI, and run host-side recovery export/import against the approved Sprint 5 TEST-ONLY fixture authority with `ConsumedRecoveryNonces` replay protection — all wired through `Dobby.Infrastructure.Persistence` and `Dobby.Infrastructure.ProtectedStorage` without weakening Sprint 3/4 floors and without pulling Sprint 6+ work.
- Why this sprint exists: Sprint 4 produced the durable encrypted persistence, protected-storage scope wrappers, the closed 11-table pre-login schema, durable `IAuditTrail`, and the `PersistenceOpened` startup milestone gated before `LoginVisible`. Sprint 5 is the first sprint that turns those tables and surfaces into the documented user-visible auth/session/recovery behavior and owns the AC-001/AC-002/AC-007 (host-side)/AC-025/AC-026/AC-028/AC-029/AC-044/AC-045/AC-050/AC-051 (skeleton) primary criteria, plus the AC-008 offline-login contribution.
