## 5. Current Codebase State

`Dobby.Licensing` currently contains only a small runtime-mode mapper. It maps `Active` to `FullAccess`, `ReadOnly` to `ReadOnlyExpired`, and `Pending`/`Denied` to `Denied`; it has no `.dobbylicense` parser, canonical JSON writer, signature verifier, device fingerprint v1, import service, durable state store, revision policy, lifecycle model, or enforcement policy (evidence: `src/Dobby.Licensing/Dobby.Licensing.csproj`, `src/Dobby.Licensing/LicenseRuntimeModeMapper.cs`, `tests/Dobby.UnitTests/Licensing/LicensingTests.cs`).

The plugin-visible contract already has the canonical `PluginRuntimeMode` enum with exactly `FullAccess`, `ReadOnlyExpired`, and `Denied`, and `ICapabilityLicensing.GetCurrentMode()` exists. Sprint 9 must not add enum values or raw license detail to Contracts/SDK (evidence: `src/Dobby.Contracts/Licensing/LicensingContracts.cs`, `tests/Dobby.UnitTests/Contracts/PluginContractDefaultsTests.cs`, `docs/adr/ADR-0053-capability-surface-runtime-mode.md`).

## 6. Docs and ADR Alignment

ADR-0051 is the canonical lifecycle source. It supersedes ADR-0026, defines `.dobbylicense` v2 detached vendor-signed JSON, mandatory payload/signature fields, canonical JSON signing rules, verification order, device fingerprint v1, revision monotonicity, lifecycle states, and runtime-mode mapping (evidence: `docs/adr/ADR-0051-license-lifecycle-v2.md`).

ADR-0052 is the canonical customer/deployment context source. Phase 1 has one active context with canonical `customerId = "default"` and `deploymentId = "default"`; license import validates this existing context and never creates or changes it opportunistically. ADR-0052 consequences and the architecture map assign host-internal current-context ownership to `Dobby.Security / Current Context`; the storage table exists today, but Sprint 9 must explicitly materialize or verify the default row through that Security owner and provide a current-context lookup seam before calling license binding checks (evidence: `docs/adr/ADR-0052-tenant-customer-context-v2.md`, `docs/02_ARCHITECTURE_MAP.md`, `artifacts/release-evidence/skeleton-local/storage-materialization.md`, `src/Dobby.Infrastructure/Persistence/PreLoginMigrationV1.cs`, `src/Dobby.Infrastructure/Persistence/HostPersistenceMigrator.cs`).

ADR-0053 is the canonical capability/runtime-mode source. Plugins only see `PluginRuntimeMode` through `ICapabilityLicensing.GetCurrentMode()`, while host enforcement is authoritative across storage writes, command/action pipeline, background tasks, import/export/report/file output, and print target classification (evidence: `docs/adr/ADR-0053-capability-surface-runtime-mode.md`, `src/Dobby.Contracts/Licensing/LicensingContracts.cs`).

The license import spec is the canonical flow source. It names `Plugins > License`, the `plugins.license.view/import` permission target, reject vocabulary, ReadOnlyExpired recovery exception, audit events, and artifact attestation requirements (evidence: `docs/specs/license-import.md`).

The JSON schema is canonical for the wire shape, but using `JsonSchema.Net` for license schema validation is not already approved. Sprint 8 approval and current package governance restrict `JsonSchema.Net` to plugin manifest validation, so Sprint 9 either uses BCL/manual validation against the schema requirements or obtains a separate human approval before widening package use (evidence: `docs/schemas/dobby-plugin-license.schema.json`, `SPRINT_8_EXECUTION_PLAN.md`, `tests/Dobby.IntegrationTests/Architecture/PackageGovernanceTests.cs`).
